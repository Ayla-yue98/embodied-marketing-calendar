# 具身营销日历

新版网页与原附件分开保存。直接打开 `index.html` 即可浏览，不需要安装软件。它支持公司、年份、月份、来源状态和关键词筛选，月度 / 全年切换，出处查看及 CSV 导出。

## 发布与维护

网站及更新配置保存在 [GitHub 仓库](https://github.com/Ayla-yue98/embodied-marketing-calendar)，默认分支为 `main`，Pages 使用 GitHub Actions 发布。

需要立即更新时，在仓库 **Actions → Update marketing calendar and publish → Run workflow** 运行即可。执行结果可在该页查看；网页「更新与来源」显示实际采集日期及各公司的采集状态。

发布配置已包含月度定时任务：北京时间每月 1 日 10:00 触发，补充上一个月及重叠窗口内的官网新闻，保留历史数据，再发布到同一网址。GitHub 的定时任务可能延迟；页面显示实际采集时间。工作流仅发布生成的 `index.html`，没有上传原附件。

默认网页可由持有网址的人访问，公开仓库中的数据也可查看。如团队必须使用登录或访问限制，需要改用支持团队访问控制的发布平台。

## 更新范围与口径

- 覆盖宇树、云深处、波士顿动力、智元、优必选、银河通用、傅利叶。
- 自动采集公司官网公开新闻。无法访问、缺少日期或动态渲染的入口会留下状态记录；不会把失败误写为「没有发生动作」。官网未收录的社媒、KOL、演出和赛事动作仍需另外检索补充。
- 傅利叶使用其官网页面自身调用的公开新闻接口；如果接口返回空列表，记录为「接口当前返回 0 条」，保留历史条目，不据此推断公司没有营销动作。
- 品牌营销 / PR / 产品营销根据标题自动归类，采集记录均为「官网采集 · 待核实」。人工核实后可将相应记录标为 `verified`，并补充依据与实际事件日期。
- 采集日期为官网**发布日期**，界面明确标注「报道月」。不会把发布日期直接写成活动发生日期，不收录当前日期之后的新闻。
- 原附件没有出处的记录标为「原稿待核实」。没有年份或持续型动作单独归档。原稿中的策略判断不作为事实直接发布。
- 公司披露的销量、订单、量产和领先性表述属于公司口径，不代表独立验证。
- 相同文章按 URL 去重；不同文章报道同一活动时可能形成多条记录。统计单位是「记录」，不是去重后的行业事件总数。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `index.html` | 可直接打开的网页；唯一上线发布文件 |
| `data.json` | 记录、出处、导入信息和采集日志 |
| `sources.json` | 七家公司官网入口与允许的域名 |
| `update.py` | 官网采集、日期检查、去重和网页重建 |
| `build.py` | 将数据、样式与交互构建为单文件网页 |
| `template.html` / `styles.css` / `app.js` | 页面源文件 |
| `.github/workflows/monthly-update.yml` | 线上月度更新及发布配置 |
| `tests/test_update.py` | 日期、去重、未来日期与失败状态检查 |

程序只依赖 Python 标准库，不使用生成式模型或付费 API，也不使用图片网关密钥。

本机维护命令（在本文件夹运行）：

```sh
python3 -m unittest discover -s tests -v
python3 update.py
python3 build.py
```

添加人工核实的事件时，保留稳定 `id`、公司 `company`、类别 `category`、实际日期 `date` 和来源 `sources`。自动采集程序会保留已有记录，抓取失败也不会删除历史内容。
